# Ssh tabs must outlive their connections

Across about thirty terminals and ssh clients, the tab bar has settled on a common floor. That floor is **Ctrl+Shift+T to open, Ctrl+Shift+W to close, Ctrl+PgUp/PgDn to switch, Ctrl+Shift+PgUp/PgDn to move, a jump to tab N, drag to reorder, a new tab that inherits the current directory, and a close prompt only when something is running**. A user coming to puritty from any of them will take all of it for granted. The demand beyond the floor is measurable, and it is lopsided. The most-reacted tab requests anywhere are **opening a new tab where the current one is (535 👍 on Windows Terminal), tear-out (326 on Windows Terminal, 317 on Warp), session restore (689 on Ghostty, 254 on Windows Terminal) and broadcast input (415 on Ghostty)**. The complaints that recur over twenty years are a different list. Tab shortcuts steal keys from vim and readline and cannot be unbound. Titles do not say which host a tab is. Users cannot see which background tab needs them. Close confirmations come too often or too rarely. The ssh-first clients that PuTTY and MobaXterm users move between (MobaXterm, SecureCRT, Xshell, Termius, Royal TS) add a model the local terminals lack: **a tab is a live instance of a saved session**, so it can be duplicated, it shows a red or "disconnected" state, it reconnects in place, it carries a per-host color, and it can be one target in a broadcast to a chosen subset. For puritty, the survey supports TA3's order (local tabs first, tear-off last) but argues for three changes. Reconnect-in-tab and the disconnected state belong in the first tab release. Broadcast should reach across tabs, not only a tab's panes. Restore is cheap for ssh tabs and ranks above splits in user demand.

## A dozen behaviours are now the floor, and the libadwaita terminals have converged on them

Reading the current source of the Linux terminals shows the same default bindings in nearly every one ([linux notes](./../research_notes/Terminal%20tabs%20survey/linux_desktop_terminals.md)). GNOME Terminal's schema defaults to **Ctrl+Shift+T, Ctrl+PgUp/PgDn, Ctrl+Shift+PgUp/PgDn, and Alt+1…9 with Alt+0 for the tenth tab**. Its tab bar is hidden at one tab, and it confirms on close. Ptyxis, now the default terminal in Fedora Workstation, RHEL and Ubuntu, has the same keys plus **undo-close-tab on Ctrl+Shift+Alt+T**, session restore on by default, and a searchable tab overview with pinned tabs ([Ptyxis README](https://gitlab.gnome.org/chergert/ptyxis/-/raw/main/README.md), [It's FOSS](https://itsfoss.com/ptyxis-terminal-features/)). xfce4-terminal has the same core plus undo-close, an activity color on the tab, and a title mode (replace, prepend, append, hide) that settles how a user's title and a program's title combine ([xfce docs](https://docs.xfce.org/apps/xfce4-terminal/start)). Terminator, the colleague's reference, has new tab at end or after current, switch and move on the PgUp/PgDn chords, wheel over the bar, double-click rename where an empty name reverts to the program's title, a close button plus middle-click, drag-out to detach, and a bar on any edge. It has **no default keys for jumping to tab N** (`docs/terminator.md` TA1). Konsole and Yakuake are the outliers: they switch tabs with Shift+Left/Right ([Konsole command reference](https://docs.kde.org/stable_kf6/en/konsole/konsole/commandreference.html)).

The cross-platform terminals agree on the semantics but differ on one design choice that matters for puritty: who draws the bar. Ghostty uses native widgets: libadwaita's `TabView` on Linux and NSWindow tabs on macOS. That gave it drag-out and an overview cheaply, but a maintainer says side tabs are "not something that's going to be developed any time soon" because libadwaita lacks them ([ghostty#2549](https://github.com/ghostty-org/ghostty/discussions/2549)), and macOS 27 broke its tab bar badly enough to draw a 53-upvote thread ([ghostty#14244](https://github.com/ghostty-org/ghostty/discussions/14244)). kitty and WezTerm draw their own bars. kitty gets vertical tabs, title templates, filters and activity and bell symbols ([kitty.conf](https://sw.kovidgoyal.net/kitty/conf/)). WezTerm still cannot drag to reorder after five years ([wezterm#549](https://github.com/wezterm/wezterm/issues/549), 133 👍). puritty draws its own bar already, for tmux. It therefore avoids Ghostty's breakage, but it has to build drag, overflow and accessibility itself.

| behaviour | consensus default | who differs |
|---|---|---|
| new tab | Ctrl+Shift+T (Cmd+T on macOS) | Konsole and Yakuake are the same; MobaXterm uses Ctrl+Alt+T |
| switch | Ctrl+PgUp/PgDn; Ctrl+Tab in Guake, Windows Terminal, MobaXterm | Konsole and Yakuake use Shift+←/→ |
| move | Ctrl+Shift+PgUp/PgDn, plus drag | Konsole uses Ctrl+Alt+←/→ |
| jump to N | Alt+1…9, Alt+0 (GNOME family, Yakuake) | Guake uses Ctrl+F1…F10; MobaXterm Ctrl+Alt+F<n>; Terminator has none |
| new tab position | split: `last` (GNOME, Terminator) vs after current (Ghostty, Windows Terminal option) | every one makes it a setting |
| working directory | inherit (Ghostty #1392, 105 👍; Windows Terminal #3158, 535 👍) | GNOME Console did not, and it blocked Ubuntu adopting it ([Phoronix](https://www.phoronix.com/news/GNOME-Console-Ubuntu-22.10)) |
| bar with one tab | hidden (GNOME, Ghostty, kitty, Konsole since 22.12) | "always show" is Terminator's most-reacted tab issue ([terminator#457](https://github.com/gnome-terminator/terminator/issues/457)) |
| close prompt | only when a non-shell process runs | Ghostty prompts on an idle fresh tab when it cannot tell ([ghostty#3070](https://github.com/ghostty-org/ghostty/discussions/3070), 38 up) |

## Users vote hardest for four things: new tab in place, tear-out, restore and broadcast

The reaction counts across trackers rank the demand plainly. On Windows Terminal, the tab issues with the most 👍 are: a new tab in the same directory, **535** ([#3158](https://github.com/microsoft/terminal/issues/3158)); tab tear-off and merge, **326**, shipped in 1.18 ([#1256](https://github.com/microsoft/terminal/issues/1256), [devblog](https://devblogs.microsoft.com/commandline/windows-terminal-preview-1-18-release/)); persist and restore, **254** ([#766](https://github.com/microsoft/terminal/issues/766)); tmux control mode, **223 and still open** ([#3656](https://github.com/microsoft/terminal/issues/3656)); start with several tabs, 187; restore buffer contents, 178; and broadcast, 141. Ghostty's ranking is similar. A session manager is its most-upvoted idea at **689** ([ghostty#3358](https://github.com/ghostty-org/ghostty/discussions/3358)), followed by broadcast input to many panes at **415** ([ghostty#3227](https://github.com/ghostty-org/ghostty/discussions/3227)), a scripting API at 263, and naming tabs at 140. Warp's top tab issues all shipped: drag tabs between windows (317), vertical tabs (236), pinned tabs and groups (226), reorder (107) and rename (55) ([Warp#466](https://github.com/warpdotdev/Warp/issues/466), [Warp#2155](https://github.com/warpdotdev/Warp/issues/2155), [Warp#2314](https://github.com/warpdotdev/Warp/issues/2314)). Hyper never added drag reordering, which had about 130 reactions on each of two 2016 issues, and it is now archived ([hyper#39](https://github.com/vercel/hyper/issues/39)).

Two other results matter for puritty. First, tear-out is persistently wanted and persistently buggy. It has been open in Tabby since 2018 ([tabby#581](https://github.com/Eugeny/tabby/issues/581), 54 👍) and in ConEmu since 2015. In Windows Terminal, after it shipped, dragging a tab out could close the whole program ([#18561](https://github.looper.workers.dev/microsoft/terminal/issues/18561)). Konsole can drag tabs between windows only in single-process mode, and not at all on Wayland ([KDE 403324](https://bugs.kde.org/show_bug.cgi?id=403324), [KDE 436914](https://bugs.kde.org/show_bug.cgi?id=436914)). Terminator has a 2026 crash from dragging a tab back over its own bar ([terminator#1140](https://github.com/gnome-terminator/terminator/issues/1140)). Konsole's single-process restriction is the same constraint as puritty's one window per process. Second, keyboard alternatives to dragging exist and are accepted: Windows Terminal's `moveTab` takes `"window": "new"` ([WT actions](https://learn.microsoft.com/en-us/windows/terminal/customize-settings/actions)), and Ghostty has `move_tab_to_new_window` ([ghostty#2630](https://github.com/ghostty-org/ghostty/issues/2630), closed as implemented).

Vertical tabs show steady but smaller demand: 236 on Warp, 78 on Ghostty, 46 on WezTerm, and maintainers called the idea sensible on Windows Terminal ([#16387](https://www.github.com/microsoft/terminal/issues/16387)). For people who keep many ssh sessions, the request it answers, seeing many sessions at once, is already met in the ssh clients by a host tree with open-session markers. MobaXterm 26.1 added dots in the session tree for open sessions, and clicking one jumps to its tab ([MobaXterm changelog](https://mobaxterm-en.mobatek.net/download-home-edition.html)).

## Twenty years of complaints: stolen keys, blank titles, silent tabs, wrong prompts

**Key collisions are the oldest and most repeated complaint.** gnome-terminal hard-coded Ctrl+PgUp/PgDn so that vim users could not get them back ([Debian 747242](https://lists.alioth.debian.org/pipermail/pkg-gnome-maintainers/2014-May/110707.html)). Red Hat recorded them being captured "even with a single tab open" ([RH 1268255](https://bugzilla.redhat.com/show_bug.cgi?id=1268255)). Gentoo has a report of vim breaking from 2006 ([Gentoo 142117](https://bugs.gentoo.org/142117)). xfce4-terminal swallowed the keys even with the shortcut disabled ([xfce 10469](https://bugzilla.xfce.org/show_bug.cgi?id=10469)). Ctrl+Tab is the mirror case. Users ask for it to be bindable ([gnome-terminal#279](https://gitlab.gnome.org/GNOME/gnome-terminal/-/issues/279), [Guake#152](https://github.com/Guake/guake/issues/152), 23 👍), and others ask for it to be freed for the program inside. Whether Ctrl+Tab should cycle in most-recently-used order split Windows Terminal's users almost evenly, **8 against 7** on the maintainer's comment. The project shipped `tabSwitcherMode = mru | inOrder | disabled` with a visible overlay, because MRU without one "doesn't really work" ([WT#973](https://github.com/microsoft/terminal/issues/973)). One further collision was not found in a tracker and is flagged here as uncited: Alt+digit is readline's numeric-argument prefix, so the GNOME family's Alt+1…9 takes a key from shell users.

**Titles that say nothing about the host.** By default a tab title is "bash" or whatever the remote shell sends, and over ssh the remote shell's OSC title replaces the local one ([WezTerm shell integration](https://wezterm.org/shell-integration.html)). GNOME Terminal removed Set Title in 3.12. Users complained that "commanding the label change via PS1 is not convenient, especially if I am logged to a remote computer" ([gnome-terminal#182](https://gitlab.gnome.org/GNOME/gnome-terminal/-/issues/182)) and asked for an "immutable tab title prefix" that a program cannot overwrite ([Ubuntu Discourse](https://discourse.ubuntu.com/t/gnome-terminal-removed-features-such-as-setting-immutable-tab-title/9508)). Rename is still missing in GNOME Console and has been open in Tilda since 2015 ([tilda#134](https://github.com/lanoxx/tilda/issues/134)). iTerm2 fixed a user-set title being replaced by the session name only in 3.7.5 ([iTerm2 changelog](https://iterm2.com/downloads)). Royal TS users asked for the folder name in the tab title so that same-named hosts in different folders can be told apart ([Royal community](https://community.royalapps.com/t/folder-name-in-tab-title/530)). Ghostty's inline rename field cannot take Cmd+C ([ghostty#10749](https://github.com/ghostty-org/ghostty/issues/10749), 93 👍). The fix most terminals converged on is a title *mode*, not a single override: xfce4-terminal's replace, prepend or append; Ptyxis's "prepend a name to the process title"; Terminator's "empty reverts".

**Which background tab needs me.** Requests for activity and bell marks run from 2004 to 2026. GNOME Terminal users have asked for years ([LP 392175](https://bugs.launchpad.net/gnome-terminal/+bug/392175)). Windows Terminal has an open request with 62 👍 ([#7955](https://github.com/microsoft/terminal/issues/7955)), and Ghostty one with 21 ([ghostty#10692](https://github.com/ghostty-org/ghostty/discussions/10692)). The 2025–26 driver is several coding agents running in tabs, where "there's no way to see which one needs attention without focusing each tab" ([Cursor forum](https://forum.cursor.com/t/cli-show-idle-working-needs-approval-in-the-terminal-tab-title-like-codex/169352)). iTerm2 3.7 answers it with a per-tab subtitle, color and dot ([AlternativeTo](https://alternativeto.net/news/2026/9/iterm2-3-7-released-with-ios-companion-app-claude-code-integration-tab-groups-and-more/)). The working designs are kitty's `bell_on_tab` and `tab_activity_symbol`, iTerm2's new-output dot, activity spinner and session-ended icon, MobaXterm's blue dot, and Termius's green for unread, yellow for input needed and red for failed ([Termius docs](https://docs.termius.com/terminal/workspaces)).

**Close confirmation, wrong in both directions.** Kovid Goyal's view is that a terminal should not ask ([kitty#734](https://github.com/kovidgoyal/kitty/issues/734)). Windows Terminal users asked for prompts before closing a tab (26 👍) and a pane (48 👍), and to customise the exit prompt (49 👍). The rule that works is Konsole's and Ghostty's: ask only when a non-shell process is in the foreground, and allow always and never overrides ([Unix.SE discussion](https://wiki.neonvagabond.xyz/content/unix.stackexchange.com_en_all_2024-05/questions/703943/how-can-the-terminal-emulator-tell-whether-it-s-safe-to-close-the-window-or-it)). Closing by accident is the other half. Reopen-closed-tab is requested in iTerm2, Konsole and kitty, mostly "to get back the log history you just lost" ([iTerm2#9890](https://gitlab.com/gnachman/iterm2/-/issues/9890)). Warp keeps closed tabs for 60 s ([Warp tabs](https://docs.warp.dev/terminal/windows/tabs/)), and iTerm2 for five.

**Smaller but repeated:** the active tab is hard to tell from the others ([WT#771](https://github.com/microsoft/terminal/issues/771), [ConEmu#552](https://github.com/ConEmu/ConEmu/issues/552), [xfce#296](https://gitlab.xfce.org/apps/xfce4-terminal/-/issues/296), [KDE 512695](https://bugs.kde.org/show_bug.cgi?id=512695)). A Warp redesign that weakened the highlight drew 46 reactions asking to bring it back ([Warp#6629](https://github.com/warpdotdev/Warp/issues/6629)). Full-width tabs make scanning harder ([Guake#962](https://github.com/Guake/guake/issues/962), 22 👍). The mouse wheel switches tabs unexpectedly ([xfce#235](https://gitlab.xfce.org/apps/xfce4-terminal/-/issues/235), [KDE 451810](https://bugs.kde.org/show_bug.cgi?id=451810)), while Rio users ask for exactly that ([rio#1917](https://github.com/raphamorim/rio/issues/1917)). Keyboard focus does not land in a new tab ([WT#13388](https://github.com/microsoft/terminal/issues/13388), 62 👍). After a close, the wrong neighbour is selected ([KDE 492069](https://bugs.kde.org/show_bug.cgi?id=492069)). The window resizes when a tab closes or the bar appears ([ptyxis#338](https://gitlab.gnome.org/chergert/ptyxis/-/issues/338)). Closing a tab that holds splits crashes the terminal ([KDE 498846](https://bugs.kde.org/show_bug.cgi?id=498846), [terminator#1120](https://github.com/gnome-terminator/terminator/issues/1120)). One item bears directly on puritty's Korean users: Ghostty loses **Korean IME composition on tab switch** ([ghostty#15064](https://github.com/ghostty-org/ghostty/discussions/15064), 2026-11-04).

## The ssh clients treat a tab as a live instance of a saved session

The clients PuTTY and MobaXterm users actually move between share a model that the local terminals do not have. MobaXterm opens tabs from a session tree and can launch every session in a folder at once. It duplicates a tab (Ctrl+Shift+U), gives each tab a color, turns the tab text red when the session is disconnected, offers "Display reconnection message at session end", can lock the title to the session name, and has MultiExec, which types into all tabs with per-tab exclusion ([MobaXterm docs](https://mobaxterm-en.mobatek.net/documentation.html), [changelog](https://mobaxterm-en.mobatek.net/download-home-edition.html)). SecureCRT colors tabs by status (connected, disconnected, new input, inactive, locked), has a Reconnect Tab action, and since 9.0 gives each tab **its own font and character encoding**, with an option to "Reuse disconnected tabs" ([SecureCRT 9.0 history](https://www.vandyke.com/download/securecrt/9.0/history.txt)). Its Command window sends to all connected sessions or to chosen tab groups ([VanDyke](https://www.vandyke.com/support/tips/chatsendcom.html)). Xshell sends to all sessions, to connected sessions only, or to **tabs of the same color** ([NetSarang KB](https://netsarang.atlassian.net/wiki/x/HoKsQg)). Termius renames a tab without renaming the host and marks status by color ([Termius](https://docs.termius.com/terminal/workspaces)). Tabby made the behaviour on disconnect configurable (close, keep or reconnect) and added a reconnect hotkey ([Tabby changelog](https://www.softpedia.com/progChangelog/Terminus-Pankov-Changelog-257708.html)). Windows Terminal added `restartConnection` "especially useful for scenarios like ssh" ([WT actions](https://learn.microsoft.com/en-us/windows/terminal/customize-settings/actions)).

Broadcast differs in scope across these clients, and the difference bears on TA3. Windows Terminal broadcasts only to "all panes in the same tab". MobaXterm sends to all tabs. SecureCRT sends to groups or connected sessions. Xshell sends to same-colored tabs. Termius sends to the workspace. The ssh clients broadcast **across tabs**, because their users' unit is the host, and their hosts are tabs.

The surrounding market explains why puritty has an opening. The stock complaint is that "PuTTY is the smoothest for SSH but the lack of tabs means it's too cumbersome … with multiple sessions" ([The Register forum](https://forums.theregister.com/forum/all/2020/08/27/windows_terminal_update/)). The answers people find each cost something. MobaXterm Home caps saved sessions at 12 ([fitgap](https://us.fitgap.com/products/016680/mobaxterm)) and is called dated and crash-prone with many sessions. SecureCRT starts at $119. Tabby's own README says it is not lightweight ([Tabby](https://github.com/Eugeny/tabby)). SuperPuTTY and MTPuTTY re-parent PuTTY's windows and keep producing focus and Alt+Tab bugs ([SuperPuTTY](https://jimradford.github.io/superputty)). KiTTY still has no tabs. On Windows the window manager offers no tabbing, which is why Alacritty's "use your window manager" stance drew its hardest pushback from Windows users running "different shells often even on separate VMs" ([alacritty#3129](https://github.com/alacritty/alacritty/issues/3129#issuecomment-684052781)). One tmux session cannot hold tabs to different hosts, so puritty's tmux-only tabs do not cover this case.

## iTerm2's tmux -CC shows where native tabs and a multiplexer collide

iTerm2 is the reference for tabs over tmux. Each tmux window is a native tab, and native keys, scrollback, find and copy work. Users praise it as "the remote development setup nobody talks about" ([DEV](https://dev.to/evoleinik/iterm2-tmux-cc-the-remote-development-setup-nobody-talks-about-4p89)), and it is a main reason people stay on iTerm2 ([comparison](https://tslateman.github.io/tutor/how/terminal-emulators)). Its friction falls in the places puritty has already decided. Closing a tmux tab kills the tmux window ([tmux integration](https://iterm2.com/documentation-tmux-integration.html)), and users who expected it to keep the session were surprised ([iTerm2#9731](https://gitlab.com/gnachman/iterm2/-/issues/9731)). Cmd+W offers kill, hide or cancel but not detach, and George Nachman agreed detach belonged there ([iterm2-discuss](https://groups.google.com/g/iterm2-discuss/c/rrcj-wtsAEc)). Tab titles and colors survive reattach through tmux options, but tab groups do not ([iTerm2#13167](https://gitlab.com/gnachman/iterm2/-/issues/13167)). All tmux windows share one size, which leaves grey gutters. iTerm2 forbids mixing local and tmux panes in one tab. When the user asks for a new tab inside a tmux integration session, it asks whether that tab should be local or tmux ([menu items](https://iterm2.com/documentation-menu-items.html)).

This supports puritty's choice to have no close button on tmux tabs, and it adds two points for when local tabs arrive. First, when a tmux -CC session and local tabs share a window, each "new tab" must have an obvious answer to whether it is local or tmux, and the two kinds of tab need a visible difference. Second, an explicit Kill / Detach choice is better than silence for the user who reaches for Ctrl+Shift+W on a tmux tab. The vertical-space argument from tmux users ("tabs steal a bit of screen real-estate", [dev.to](https://dev.to/thermatix/devs-why-do-you-use-terminal-tabs-over-tmux-windows--51hb)) is the argument for keeping a one-line "tmux look" as an option for local tabs too.

## Where the evidence agrees and disagrees with TA3

TA3 (`docs/terminator.md`) proposes local tabs, then splits and broadcast within a tab, then saved layouts, with tab-to-window last.

**Agreement.** Local tabs first is right. They are what "tab management" means to most users, and on Windows, with no tabbing window manager, they are table stakes rather than an extra. TA3's key list (Ctrl+Shift+T, Ctrl+PgUp/PgDn, Ctrl+Shift+PgUp/PgDn, Ctrl+Shift+W) is the consensus floor exactly. So are rename by double-click, drag to reorder, and the bar at top or bottom. Reusing the self-drawn tmux bar in both looks is supported: self-drawn bars avoid Ghostty's OS-update breakage, and the tmux look answers the vertical-space objection. Putting tab-to-window last is defensible. Tear-out has high demand (326 and 317 reactions), but it is a bug farm even in mature multi-window programs. Konsole manages it only in single-process mode, which is puritty's constraint. A keyboard "move this tab to a new window" is an accepted alternative. For an ssh tab, that could be "open this host in a new window", which reconnects in a new process rather than moving live state. That is an inference; no surveyed client does it.

**Disagreement or gaps.** First, TA3's tab item has none of the ssh-session behaviour that defines the products puritty aims to replace. Every ssh-first client has reconnect in place, a visible disconnected state, duplicate tab, a per-host tab color, and a title that defaults to the session name. These belong in step 1, not later, because an ssh tab that silently closes on disconnect, or shows only the remote shell's title, fails the MobaXterm comparison on day one. Second, TA3 ties broadcast to a tab's panes and so places it after splits. That is Windows Terminal's scope. The ssh clients broadcast across tabs, to all of them, to a chosen subset, or by color. Ghostty's 415 upvotes and MobaXterm's MultiExec show the demand. Cross-tab broadcast needs no splits and can come straight after tabs. Third, restore ranks above splits in measured demand (689 and 254 against 140 for Windows Terminal's panes umbrella). For ssh tabs, restore means reopening host-list entries in order with their names and colors. That is far cheaper than restoring a local shell's state, so TA3's step 4 can move up, in its ssh form. Fourth, TA3 makes middle-click close and wheel switching unconditional. Both draw complaints in both directions: GNOME deliberately blocks middle-click close ([gnome-terminal source note, issue #75](https://gitlab.gnome.org/GNOME/gnome-terminal/-/issues/75)), and the wheel draws xfce, Yakuake and Rio reports. Both should be settings, and a middle-click on a connected ssh tab should go through the close prompt.

## What puritty's local tabs must do, should do, and must avoid

The ranking below weighs the measured demand above, the cost of absence for a PuTTY or MobaXterm user, and fit with puritty's one-window-per-process, ssh-first design. Each "puritty look / traditional" choice the owner wants is noted where the survey shows a real split.

**Must do (ranked)**

| # | item | why |
|---|---|---|
| 1 | Every tab key rebindable and removable; tab keys inert with one tab where the bar is hidden | The oldest complaint (Debian 747242, RH 1268255, Gentoo 142117); vim and tmux users need Ctrl+PgUp/PgDn and Ctrl+Tab back |
| 2 | Consensus keys and mouse: Ctrl+Shift+T, Ctrl+Shift+W, Ctrl+PgUp/PgDn, Ctrl+Shift+PgUp/PgDn, drag to reorder, double-click rename, click `+` | The floor in every surveyed terminal; matches TA3 and puritty's tmux tabs |
| 3 | New tab "where I am": a local tab inherits the cwd (OSC 7 or /proc); from an ssh tab, offer the same host (duplicate session) | Windows Terminal's most-reacted tab issue (535), Ghostty 105, Hyper 134; MobaXterm and SecureCRT duplicate |
| 4 | An ssh tab survives its connection: a disconnected state on the tab, reconnect in place by key and click, no automatic close | MobaXterm red text, SecureCRT and Termius status colors, Tabby #8206, WT `restartConnection` |

## Conclusion

The survey changes what "tabs" means for puritty. For a local terminal the feature is a solved shape, and the work is in the details users fight over: key ownership, titles, attention marks and close rules. For an ssh client a tab is a session object. Reconnect, the disconnected state, duplication, color, restore and broadcast are all properties of that object, and none of them depends on splits. That reorders TA3 without overturning it. Local tabs still come first, and tear-off still comes last, but the first release should include the ssh-session behaviour that MobaXterm and SecureCRT users would otherwise miss on day one. Broadcast and restore can follow directly, ahead of splits, because the ssh clients deliver both across tabs.

Two uncertainties remain. The evidence is tracker reactions and forum posts. No user study of tab workflows exists, and Reddit was largely unreachable, so the rankings reflect the vocal users who file issues. Terminator users are under-measured as well: its most-reacted tab issue has only 8 👍, so the colleague's preference for its splits and broadcast is better tested by asking him what he uses daily than by inferring it from its trackers. Puritty has one structural advantage the survey makes visible: it owns the ssh client. It knows the host, the connection state and the encoding without shell integration. That is the information local terminals guess at when they build per-host colors, meaningful titles and safe close prompts.
